# Стресс-сценарии

Это окончательно подготовленный комплект данных, версия 2. Ассистент проверил логику и формат. Проверка человеком и запуск LLM ещё не выполнены. Предыдущие черновики в stress/drafts сохранены для истории; для продолжения используется этот комплект.

Всего 17 наборов, 28 пар «вариант–вопрос», 84 вызова при трёх режимах. Перестановка относится ко всем 12 вопросам; удаление — к четырём multi-hop и временным вопросам. Десять добавлений создают конфликт, ещё два — контроль неподтверждённых сведений для исходно insufficient вопросов. Эти два контроля не выдаются за создание противоречия и не включаются в метрику перехода к both.

Сравнивать каждый вариант только с исходным досье, не применять изменения последовательно друг к другу. Порядок остальных документов сохранён. C41/D11 существуют отдельно в каждом добавлении, а не обозначают один общий источник для всех сценариев. Во всех режимах запрещено передавать модели эталоны, спецификации изменений или скрытую авторскую хронологию.

Изменение считается одним смысловым фактором: один факт скрывается вместе со всеми раскрывающими его повторами и производными выводами либо добавляется одно несовместимое сообщение. Удаление исходного C40 вместе с временной посылкой не является вторым независимым воздействием. Изменение ожидаемого ответа служит разметкой и не входит в контекст LLM.

## Как проверять

В каждой папке находятся documents.jsonl, claims.jsonl, questions.jsonl, claims_metadata.json, scenario.json и changes.patch. В questions.jsonl указан конкретный новый ответ, включая недостающую информацию для insufficient. Снимок исходного набора находится в _baseline.

Для подтверждения фактической проверки человеком: `.venv/bin/python scripts/review_scenario.py stress/scenarios/ИМЯ --reviewer "Имя участника"`. Команду выполняют после просмотра изменений и эталона. Она сохраняет хеш проверенного набора; любая последующая правка требует повторной проверки. Ассистент не выставляет human_reviewed=true за человека.

Максиму нужно выполнить исходные и изменённые наборы одной моделью API, с теми же параметрами и промптом. Ответы сохранить до ручного анализа. Для перестановки сравнить долю сменившихся статусов и Jaccard доказательств; для удаления — долю ответов с ожидаемым insufficient; для добавления противоречия — долю ожидаемых both. Отдельно показать, что Q09 уже был both, поэтому здесь оценивается сохранение конфликта, а не переход в него. Для двух неподтверждённых сообщений считать сохранение insufficient отдельно.

У задания есть неоднозначность: общая фраза требует три теста для всех 12 вопросов, но удаление явно ограничено multi-hop и временными; из исходного insufficient нельзя автоматически получить both добавлением одного сообщения. Здесь применимость зафиксирована честно. Контроли Q11–Q12 дают проверку добавления информации для всех вопросов, но не подменяют формальное требование о несовместимом утверждении. Если преподаватель требует именно конфликт для каждого insufficient-вопроса, это потребует отдельной постановки, а не выдуманного эталона both.

### remove_Q03

Связана ли ошибка проверки лобби с B18 с тем, что пакет ссылается на отсутствующий на финальном сервере ресурс?

**Ответ:** Нельзя установить причину ошибки после удаления сведений о доступности arena_trial. В досье остаются ссылка B18 на arena_trial и неуспешная проверка, но отсутствует необходимое основание об отсутствии ресурса.

**Статус:** insufficient. **Основания:** C27, C08. **Контроснования:** нет.

### contradiction_Q01

**Ответ:** Основной журнал указывает 18:10:00, альтернативный журнал отрицает вход в этот момент. Противоречие не разрешено; однозначное время входа по этим источникам установить нельзя.

**Статус:** both. **Основания:** C01. **Контроснования:** C41.

### contradiction_Q02

Какой резервный ключ использован при восстановлении снимка S17?

**Ответ:** Источники несовместимы: основной журнал указывает R2, альтернативный — R3 вместо R2 для той же операции S17. Выбрать один источник по досье нельзя.

**Статус:** both. **Основания:** C11. **Контроснования:** C41.

### contradiction_Q03

Связана ли ошибка проверки лобби с B18 с тем, что пакет ссылается на отсутствующий на финальном сервере ресурс?

**Ответ:** Есть несовместимые основания: основная сверка и журнал связывают ошибку с отсутствующим arena_trial, альтернативная сверка сообщает о его доступности. Однозначный вывод о причине по изменённому досье невозможен.

**Статус:** both. **Основания:** C27, C28, C08. **Контроснования:** C41.

### contradiction_Q04

Совпадает ли учётная запись успешного входа в 18:10:00 с учётной записью, от имени которой выполнено восстановление S17?

**Ответ:** Есть основания обеих версий: вход в 18:10 выполнен mira; основной журнал называет оператором учётную запись restore_bot, альтернативный — mira. Совпадение учётных записей остаётся спорным.

**Статус:** both. **Основания:** C01, C41. **Контроснования:** C10.

Произошло ли восстановление S17 после назначения роли publisher учётной записи mira?

**Ответ:** Порядок спорный: при назначении publisher в 18:35 восстановление 18:28:30 было раньше, а при альтернативном времени 18:20 — позже. Приоритет одной истории ролей не установлен.

**Статус:** both. **Основания:** C09, C41. **Контроснования:** C03.

### contradiction_Q07

**Статус:** both. **Основания:** C17, C20, C24, C26. **Контроснования:** C41.

**Ответ:** Копии E04 несовместимы: исходная не распространяется на B18, альтернативная разрешает публикацию B18 заданием J18 в 18:24. Есть основания разрешённости и запрета.

**Ответ:** Местонахождение остаётся спорным: Олег сообщает о Мире в серверной, Нина и новый свидетель — у стойки интервью. Дополнительное свидетельство не устраняет конфликт автоматически.

### contradiction_Q10

Произошла ли публикация B18 в 18:18, как запомнил Олег?

**Ответ:** Время публикации спорное: исходный журнал указывает 18:24:00, новый журнал — 18:18:00. В отличие от исходного досье, теперь конфликтуют технические источники без установленного приоритета.

**Статус:** both. **Основания:** C35, C41. **Контроснования:** C07, C30.

### unverified_Q11

**Ответ:** Намерение и намеренное причинение сбоя по-прежнему не установлены. Анонимное заявление без подтверждений не доказывает ни умысел Веры, ни её физическое участие в публикации. Нужны проверяемые сведения о намерении и действиях.

**Статус:** insufficient. **Основания:** C37, C41. **Контроснования:** нет.

### unverified_Q12

Кто физически запустил восстановление S17: можно ли однозначно установить оператора по досье?

**Ответ:** Физический оператор независимо не установлен. Самоотчёт Миры и анонимный слух не заменяют персональную аутентификацию или независимую запись операции. Нужны проверяемые сведения о человеке за пультом.

**Статус:** insufficient. **Основания:** C10, C15, C32, C41. **Контроснования:** нет.
