# Досье для лабораторной № 6

Первый этап задания: создание вымышленного досье. Сюжет — сбой игрового лобби перед финалом турнира «Контур» по игре «Орбита Ноль». Все персонажи, системы и события вымышлены.

## Файлы

- `Истинная_последовательность.md` — авторский замысел, хронология, роли, причины и карта противоречий. Создан до текстов досье. Не передавать исследуемой модели и не включать в retrieval.
- `documents.jsonl` — 10 документов D01–D10 в требуемом формате, одна JSON-запись на строку. Именно этот файл предназначен для загрузки досье в будущий стенд.
- `Досье.md` — те же документы в удобном для человека виде. Это второе представление, а не дополнительные документы; не загружать его одновременно с JSONL.

Объём рассчитан только по полям `text`: разделение по пробельным символам с исключением элементов, не содержащих ни букв, ни цифр. Названия, JSON-ключи, этот файл и авторская хронология не включены в объём. Документы D09–D10 тематически связаны с турниром, но не содержат доказательств по инциденту.

## Проверка подготовки

Ассистент проверил чтение всех строк JSONL, набор обязательных полей, уникальность и порядок идентификаторов, даты с часовым поясом UTC+03:00, количество документов и объём. Проверено совпадение текстов JSONL с Markdown-представлением.

При содержательной сверке проверены последовательность публикации и восстановления, назначение обычных прав после восстановления, временные границы E04 и различие между служебной записью и физическим оператором. В D07 границы наблюдения уточнены до секунд: разговор заканчивается в 18:28:00, что не противоречит более поздней операции в 18:28:30.

Противоречие о времени публикации разрешается серверной записью и технической сверкой. Противоречие о местонахождении Миры в 18:26 сохраняется между двумя свидетельствами. Известная авторам последовательность не должна использоваться моделью как доказательство. Технические данные не доказывают намерение участников или физическую личность оператора служебной записи.

Досье подготовлено ассистентом. После создания утверждений и вопросов пользователь подтвердил в чате завершение проверки исходных материалов и эталонов. Проверка структуры JSON не подтверждает логическую корректность всех будущих ответов.

## Этап 2 — атомарные утверждения

Подготовлен `claims.jsonl`: 40 утверждений C01–C40, каждое содержит `claim_id`, `text`, `document_id`, `evidence`, `status`. Для удобного чтения создан файл `Утверждения.md` с теми же записями и пояснениями к статусам.

Распределение: 35 direct, 1 reported, 3 disputed, 1 inferred. Проверены количество записей, уникальность идентификаторов, обязательные поля, допустимые статусы, существование документов и дословное присутствие всех 40 цитат в соответствующих текстах. Статусы утверждений отличаются от будущих логических статусов ответов модели.

Временной вывод C40 основан на C09 и C03; зависимости указаны в `Утверждения.md`. При подготовке удаления посылки нужно учитывать как производные утверждения, так и повторения факта в других документах. Проверка формата и цитат сама по себе не подтверждает смысловую атомарность; пользователь отдельно подтвердил завершение проверки исходного набора.

## Вопросы и эталоны

Подготовлен `questions.jsonl`: 12 вопросов Q01–Q12, по два каждого из шести типов задания. Каждая запись содержит `question_id`, `question`, `gold_status`, `gold_answer`, `gold_evidence_ids`, `gold_counterevidence_ids`. Типы, краткие обоснования и правила интерпретации статусов приведены в `Вопросы_и_эталоны.md`.

Распределение эталонных статусов: 5 entailed, 4 contradicted, 1 both, 2 insufficient. Для Q09 сохранены обе несовместимые свидетельские версии. Для Q10 конфликт времени разрешается проверенной серверной записью; поддерживающее ошибочную версию свидетельство также сохранено. Для Q11–Q12 описаны ограничения данных и недостающая информация.

Проверены количество вопросов, распределение типов, уникальность идентификаторов, обязательные поля, допустимые статусы, существование всех ссылок на утверждения и их исходных цитат. Для both заполнены оба списка оснований. Эталоны подготовлены ассистентом; пользователь подтвердил завершение проверки исходного набора до запуска модели. Альтернативные достаточные наборы доказательств и изменения эталонов для стресс-тестов нужно согласовать до вычисления метрик.
