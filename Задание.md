# Лабораторная работа № 6. AI-детектив

Курс: Автоматическая обработка текстов

## Цель

Исследуйте поведение языковой модели при ответах на вопросы по длинному тексту, содержащему разнесенные факты, временные зависимости, правила, исключения, противоречия, нерелевантную информацию и вопросы без однозначного ответа.


## Сценарий

Команда создаёт полностью вымышленное цифровое досье и приложение для его анализа. Возможные сюжеты: сбой на киберспортивном турнире, исчезновение прототипа, конфликт вокруг командного проекта, ошибочная блокировка пользователя, утечка сборки игры, спор о результатах хакатона или инцидент в вымышленной социальной сети.


## Проверяемые способности модели

найти необходимые фрагменты;
объединить несколько посылок;
применить правило с учетом исключения;
отличить вывод от правдоподобного предположения;
обнаружить конфликт источников;
отказаться от однозначного ответа;
сохранить ответ после перестановки и увеличения текста.

### Состав

### Формат documents.jsonl


```json
{
  "document_id": "D07",

```


### Правила создания

Сначала зафиксируйте истинную последовательность событий в отдельном рабочем файле.
Создайте документы, раскрывающие только часть этой последовательности.
Добавьте противоречия, но заранее определите, можно ли разрешить их по более надежному источнику.
Добавьте нерелевантные документы, тематически похожие на полезные.
Проверьте даты, имена, роли и причинные связи вручную.
LLM разрешается использовать для создания черновиков. Ответственность за логическую согласованность остаётся на команде.


## 2. Атомарные утверждения


### Допустимые статусы

Статус
Смысл

### Файл claims.jsonl

## 5. Выход модели


```json
{
  "question_id": "Q12",
  "status": "entailed | contradicted | both | insufficient",
  "answer": "Краткий ответ либо null",
  "evidence_ids": ["C04", "C17"],
  "counterevidence_ids": [],
  "confidence": 0.78,
  "explanation": "Краткая проверяемая связь между доказательствами"
}
```


### Правила

при both заполняются evidence_ids и counterevidence_ids;
при insufficient модель указывает, какой информации не хватает;
все идентификаторы должны существовать в claims.jsonl;
confidence находится в диапазоне от 0 до 1;
объяснение должно ссылаться на доступные основания, а не вводить новые факты.
Ограничение. Не требуйте от модели скрытой подробной цепочки рассуждений. Достаточно краткого объяснения и проверяемых ссылок на утверждения.

## 6. Сравниваемые режимы


### Режим A. Полный контекст

Все документы передаются LLM в одном запросе. Порядок документов фиксируется и сохраняется.

### Режим B. Плоский retrieval

BM25 выбирает 15 наиболее релевантных утверждений. Они передаются LLM как плоский список.

### Режим C. p-adic контекст

Используются те же 15 утверждений, но они группируются по p-adic ветвям и внутри ветвей располагаются по времени. Поэтому сравнивается организация одного и того же retrieval-контекста, а не разное количество информации.
Режим
Контекст
Назначение
A
всё досье

B

проверка сокращения контекста
C

проверка структурной организации


### Контроль справедливости

используйте одну LLM и один системный промпт;
температура и остальные параметры одинаковы;
режимы B и C получают одинаковый набор claim_id;
изменяется только упаковка контекста;
сохраняйте все ответы до ручного анализа.


## 7. p-adic организация доказательств

Используйте p=3 и путь [a₀, a₁, a₂]. Код утверждения:
x = a₀ + a₁·3 + a₂·3²
Уровень
0
1
2
a₀: тип источника
системный/документальный
свидетельство
правило/интерпретация
a₁: логический статус
установленный факт
сообщение/предположение
спорное/исключение
a₂: время
до события
во время события
после/неизвестно



### Расстояние


Пусть k — число совпадающих начальных уровней. Тогда d₃(x,y)=3⁻ᵏ. Если различается тип источника, расстояние равно 1; если совпадает только источник — 1/3; если совпадают источник и статус — 1/9; при полном совпадении пути для данной работы расстояние считается нулевым.

Запрещённая реализация: abs(code_x - code_y) не является p-adic расстоянием.

### Формат режима C

ВЕТВЬ [0,0,1] — системные подтверждённые факты
C04: ...
C17: ...

ВЕТВЬ [1,2,1] — спорные свидетельства
C25: ...
C29: ...
В отчёте обсудите, почему тип источника поставлен выше времени и что изменилось бы при другом порядке уровней.

## 8. Стресс-тесты

Для всех 12 вопросов выполните три обязательных стресс-теста.

### Тест 1. Перестановка документов

Случайно измените порядок документов с random_state=42. Правильный ответ не меняется.

### Тест 2. Удаление посылки

Для multi-hop и временных вопросов удалите одно необходимое утверждение. Ожидаемый статус должен измениться на insufficient либо both, если сохраняются конфликтующие основания.

### Тест 3. Добавление противоречия

Добавьте несовместимое утверждение от другого источника. Если оснований выбрать один источник нет, ожидается переход к both.

### Фиксация результата

сохраняйте исходный и измененный состав документов;
фиксируйте ожидаемый новый статус;
не рассчитывайте тест, если изменение не прошло ручную проверку;
не изменяйте более одного фактора одновременно.
