# AI-детектив — лабораторная работа № 6

Исследовательский стенд для анализа вымышленного инцидента на турнире «Контур». Сравнивается поведение одной языковой модели **GigaChat-2-Pro** при трёх способах подачи доказательств.

## Данные и режимы

- `docs/documents.jsonl`: 10 документов, суммарный объём соответствует диапазону 5 000–8 000 слов.
- `docs/claims.jsonl`: 40 атомарных утверждений с цитатами и ссылками на документы.
- `docs/questions.jsonl`: 12 вопросов с эталонными статусами и доказательствами.
- `config/claims_metadata.json` и `config/padic_rules.md`: p-adic разметка и правила группировки.
- `prompts/system.txt`: общий системный промпт модели.

**A — полный контекст:** все 10 документов вместе с реестром 40 утверждений, позволяющим ссылаться на ID доказательств.

**B — BM25:** 15 наиболее релевантных утверждений, отобранных BM25, в плоском списке.

**C — p-adic:** ровно те же 15 утверждений, что в B, но сгруппированные по ветвям p=3 и отсортированные по времени внутри ветвей. Дополнительные данные относительно B не добавляются.

Для всех режимов используются одна модель, системный промпт и конфигурация генерации. Эталонные ответы модели не передаются.

## Быстрый запуск на Windows (PowerShell)

Требуется Python 3.11+ и доступ к GigaChat API. Выполняйте команды из корня проекта `AOT_6`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -X utf8 -m pip install -r requirements.txt
Copy-Item config\model.gigachat.example.json config\model.local.json
```

Создайте файл `.env` в корне проекта (подставьте **свои** учётные данные, не отправляйте их в Git):

```dotenv
GIGACHAT_CREDENTIALS=<ваши_учётные_данные>
GIGACHAT_CA_BUNDLE_FILE=russian_trusted_root_ca_pem.crt
```

Если в вашем окружении сертификат доверенного центра уже настроен, путь к CA bundle может не потребоваться. В этом проекте публичный сертификат расположен в `russian_trusted_root_ca_pem.crt`. Не отключайте проверку TLS.

Запуск сайта:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m streamlit run app.py
```

Откройте `http://localhost:8501`. В приложении доступны вкладки **«Исследование»**, **«Результаты»**, **«Досье»**, **«Стресс-тесты»**. Сохранённые результаты просматриваются без повторных API-запросов; кнопка нового ответа и запуск ещё не выполненного сценария обращаются к API.

## Тестирование

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q tests/test_required.py tests/test_stress_scenarios.py
```

В ходе проверки на Windows был получен результат `20 passed`. Тесты охватывают p-adic кодирование, расстояния и ультраметрику, ограничения BM25, идентичность состава B/C, валидацию ответов, реакцию на недоступность LLM и целостность стресс-сценариев. Проверка смысла естественно-языкового ответа не сводится к JSON-валидации и может требовать ручного анализа.

## Выполненные эксперименты

Основной результат: `results/gigachat_baseline_v2` — 12 вопросов × 3 режима = 36 ответов, все прошли проверку формата и доступности ссылок.

| Метрика | A | B | C |
|---|---:|---:|---:|
| Правильный статус | 11/12 | 11/12 | 11/12 |
| Evidence F1 | 0,4056 | 0,5694 | 0,5056 |

Стресс-сценарии находятся в `stress/scenarios/`:

- `permutation_42`: перестановка документов, 12 вопросов;
- `remove_Q03`–`remove_Q06`: четыре сценария удаления необходимой посылки;
- `contradiction_Q01`–`contradiction_Q10`: десять сценариев с альтернативными несовместимыми источниками;
- `unverified_Q11`, `unverified_Q12`: два **дополнительных** контроля неподтверждённых сообщений; они не являются тестами добавления противоречия.

Результаты всех 17 сценариев сохранены: **28 пар «сценарий — вопрос», 84 ответа** в режимах A/B/C. Общая таблица: `results/stress_overview.csv`.

| Метрика по 28 стресс-проверкам на режим | A | B | C |
|---|---:|---:|---:|
| Правильный статус | 20/28 | 17/28 | 23/28 |
| Формат и ссылки валидны | 26/28 | 28/28 | 28/28 |

Два ответа A были отклонены валидатором: `remove_Q03` (ссылка на недоступное утверждение) и `contradiction_Q08` (пересечение списков доказательств и контрдоказательств). Это сохранённые наблюдения, не исправленные вручную ответы модели.

Перестановка сопровождалась изменением статуса Q08 в режиме B, хотя тексты запросов B/C совпадали с исходными. Причинная связь с перестановкой не установлена.

**Замечание о токенах:** API сообщил аномально низкие входные токены (около 120–135) для части запросов режима A, хотя сохранённый контекст содержит примерно 105 000 символов. Причина не установлена. По этим данным `mean_input_tokens` не подтверждает фактический размер обработанного контекста.

## Артефакты и безопасность

- `results/`: сохранённые запросы, ответы, метрики, манифесты и сравнения.
- `AI_LOG.md`: журнал работы с ИИ, включая ошибки, принятые решения и результаты проверок.
- `ОТЧЕТ.docx`: документ отчёта (рабочая версия).
- `ANALYSIS.md`: **исторический анализ предварительного локального прогона Qwen**, не итоговые результаты GigaChat.
- `INTEGRATION.md`, `PLAN.md`: исторические организационные материалы; некоторые разделы описывают старое состояние проекта.

`.gitignore` исключает `.env`, `.env.*`, `.venv/`, локальную конфигурацию `config/model.local.json` и кэши. **Никогда не добавляйте API-ключи в репозиторий.**

## Ограничения

Один набор вымышленных документов, одна модель и по одному запуску на сценарий не позволяют обобщать результаты на другие модели и задачи. Валидный ответ не гарантирует логическую корректность; совпадение выбранных ID с эталоном не заменяет семантическую проверку. Для воспроизводимости важны сохранённые версии данных, системный промпт, конфигурация и исходные ответы в `results/`.
