# AI-детектив

Лабораторная № 6 по автоматической обработке текстов. Данные — вымышленное досье турнира «Контур». Часть Елизаветы: данные, BM25, p-adic организация, контекст, стресс-сценарии, метрики и анализ. По уточнённому разделению подключение API модели, Streamlit-стенд и полный набор обязательных тестов относятся к части Максима. Выполненный локальный прогон Qwen является предварительным.

## Подготовленные материалы

- `docs/documents.jsonl` — 10 документов, 6078 слов.
- `docs/claims.jsonl` — 40 атомарных утверждений.
- `docs/questions.jsonl` — 12 вопросов, по два каждого типа.
- `docs/Истинная_последовательность.md` — авторский рабочий файл; не загружается в модель или BM25.
- `config/claims_metadata.json` — пути и временные точки утверждений; правила описаны в `config/padic_rules.md`.
- `prompts/system.txt` — общий системный промпт.
- `INTEGRATION.md` — функции и форматы для стенда.
- `stress/REVIEW.md` — новые сценарии и порядок их проверки человеком.

Пользователь подтвердил в чате завершение проверки исходного досье, утверждений и эталонов. Это подтверждение не относится к созданным позднее стресс-вариантам и результатам модели.

## Окружение

Из корня AOT_6:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Основной код требует Python 3.11+, Pydantic 2, pandas и rank-bm25. В requirements также перечислены pytest и Streamlit для части Максима. Установленное при подготовке окружение содержит основные библиотеки и pytest; Streamlit пока не устанавливался. Версии реально использованных пакетов сохраняются в манифестах, а `requirements-core-lock.txt` фиксирует окружение основной части.

Для локальной LLM используется MLX и уже скачанный снимок Qwen2.5-3B-Instruct-4bit, revision `4f83f8f146fdf28b512a06562b671d7af4fab457`. На текущем Mac модель находится в соседней nlp_lab3; её Python-окружение используется отдельным локальным worker, чтобы не менять зависимости прошлой лабораторной и не скачивать модель повторно. Пути находятся в `config/model.example.json` и задаются относительно AOT_6. На другом компьютере нужно указать свои локальные пути. Для самостоятельного окружения модели предназначен `requirements-local-llm.txt`.

Никаких API-ключей код не требует. Автоматического скачивания модели нет. При отсутствии Metal или модели выдаётся ошибка LLMUnavailable. На текущем хосте Metal доступен вне изолированной сессии Codex.

## Подготовка и запуск

Подготовка контекстов и диагностики без вызовов модели:

```bash
.venv/bin/python -m src.experiment --output results/prepared_new
```

Полный базовый прогон:

```bash
.venv/bin/python -m src.experiment --output results/baseline_new --run
```

Папка результата должна отсутствовать или быть пустой. Существующие результаты не перезаписываются. Флаг `--limit 3` запускает только первый вопрос в A/B/C и предназначен для пилота. Пилоты не смешиваются с итоговыми метриками.

Базовый эксперимент — 36 запросов: 12 вопросов × три режима. Один системный промпт и одна конфигурация модели используются для всех режимов. Temperature=0, seed=42, максимум ответа=700 токенов. Каждый запрос независим, история диалога между вопросами не переносится. Повторного запроса для исправления невалидного ответа нет. Превышение контекстного окна не приводит к скрытому обрезанию.

## Контексты

A включает все документы в сохранённом порядке и полный реестр утверждений с идентификаторами. Реестр нужен, чтобы модель могла ссылаться на C01–C40. Поэтому A — полный текст с дополнительным реестром, что явно учитывается при обсуждении токенов.

BM25 индексирует только тексты утверждений. Токенизация приводит буквы к нижнему регистру, заменяет ё на е и выделяет буквенно-цифровые последовательности. Стемминг и внешние модели embeddings не используются. При равных оценках порядок задаётся claim_id.

B и C получают один и тот же набор top-15 и одинаковые payload, включая цитату, источник, статус, временную точку и p-adic путь. B сохраняет порядок BM25. C группирует по полному пути и сортирует внутри ветвей по времени; неизвестное время идёт в конце. C не получает дополнительных фактов или ручного выбора утверждений по эталону. Эталонные статусы и списки доказательств не попадают в запрос модели.

## Результаты

В каждом прогоне сохраняются:

- `manifest.json` — модель, revision, параметры, версии, порядок документов и хеши.
- `dataset_snapshot.json` — полный состав данных для воспроизводимости; не является промптом.
- `system.txt`, `contexts/*.txt` — реально использованный системный и пользовательские запросы.
- `contexts/*.json` — выбранные claim_id и оценки BM25.
- `answers.jsonl` — исходные ответы, результат проверки схемы, ошибки, токены и время.
- `retrieval_diagnostics.json` — покрытие выбранных эталонных оснований.
- `per_question_metrics.csv`, `summary.csv` — метрики по вопросам и режимам.

Валидный JSON не означает верный ответ: проверка схемы не выявляет все смысловые выдумки. Автоматически проверяются поля, статусы, диапазон confidence, соответствие question_id, существование и доступность ссылок, оба списка для both и отсутствие дубликатов. Содержательную проверку ответов нужно выполнять отдельно.

Метрики ссылок считаются по заранее выбранным эталонным наборам. Precision/recall/F1 пустых совпадающих наборов считаются равными 1; при невалидном ответе значения обнуляются. Counterevidence recall усредняется только по вопросам с непустым эталонным списком контрдоказательств. Помимо accuracy статуса рассчитываются precision и recall распознавания both и insufficient. Доля уверенных догадок — доля вопросов с эталоном insufficient, где модель выбрала другой статус при confidence≥0.8. Высокая уверенность в корректном отказе не считается догадкой. Порог фиксирован до базового прогона.

Токены сообщает backend с учётом chat template. Время включает подготовку входа моделью и генерацию, но исключает загрузку весов и файловую запись. Холодный кеш между запросами не принуждается, поэтому время не является строгим аппаратным бенчмарком. Для baseline по каждому типу статуса мало примеров; выводы ограничены этим досье и моделью.

## Стресс-сценарии

Подготовлены 17 актуальных наборов версии 2: перестановка для всех 12 вопросов, четыре удаления, десять противоречий и два контроля неподтверждённых сообщений. Созданы отдельные копии документов, утверждений, метаданных и изменённых эталонов. Исходные файлы в docs сохранены. Перестановка выполняется pandas.sample с random_state=42. Удаления учитывают повторы и производные выводы. Новые противоречия добавляются как D11/C41 только внутри конкретного варианта; разные варианты не смешиваются.

Логика и формат проверены ассистентом; новые варианты ещё требуют проверки человеком: в `scenario.json` стоит human_reviewed=false. После фактической проверки:

```bash
.venv/bin/python scripts/review_scenario.py stress/scenarios/remove_Q06 --reviewer "Имя участника"
.venv/bin/python -m src.experiment --output results/remove_Q06 --data-dir stress/scenarios/remove_Q06 --metadata stress/scenarios/remove_Q06/claims_metadata.json --scenario-manifest stress/scenarios/remove_Q06/scenario.json --run
```

Запуск стресс-варианта требует подтверждения проверки и совпадения хеша текущих данных с проверенным снимком. Изменение документов после проверки делает её недействительной для запуска.

Проверенный исходный набор нельзя автоматически считать проверенным изменённым набором. Метрики стресс-тестов рассчитываются только после такой проверки. Применимость каждого теста к каждому вопросу указана в `stress/applicability.json`; not_applicable не считается успешным прогоном.

## Состояние выполненной части

Базовый прогон `results/baseline_v1` завершён: 36 запросов, из них 27 ответов прошли проверку формата и доступности ссылок. Accuracy статуса: A — 5/12, B — 4/12, C — 4/12. Анализ и ограничения находятся в ANALYSIS.md; калибровочные группы — в results/baseline_v1/calibration.csv. Исходные ответы сохранены без ручного исправления.

Функции для Максима описаны в INTEGRATION.md. Подключение API, стенд, полный pytest-набор и исследовательские стресс-прогоны ещё не выполнены. Для основного эксперимента Максим должен заново выполнить baseline и стресс-варианты одной выбранной моделью API; локальные ответы Qwen с ними не смешиваются. Проверка новых стресс-вариантов человеком остаётся отдельным обязательным шагом. Пилоты в results/smoke, smoke_v2 и pilot_final_prompt не относятся к итоговому сравнению; несмотря на имя последней папки, её manifest содержит старый промпт. Итоговый промпт зафиксирован в results/baseline_v1/system.txt и manifest.json.
