# AI_LOG — лабораторная работа № 6 «AI-детектив»

**Проект:** исследование вымышленного инцидента на турнире «Контур».  
**Модель:** GigaChat-2-Pro.  
**Период работы:** ноябрь 2026 г.  

## 1. Интеграция GigaChat вместо локальной модели

- **Задача / запрос к ИИ:** подключить GigaChat к существующему исследовательскому проекту и сохранить возможность запускать режимы A/B/C.
- **Предложение ИИ:** добавить клиент GigaChat и выбор бэкенда через `src/llm.py` и конфигурацию, оставив остальную архитектуру исследования.
- **Решение команды:** использовать `GigaChat-2-Pro`, хранить учётные данные в локальном `.env`, а не в репозитории.
- **Проверка:** выполнен успешный тестовый вызов; API вернул текст `OK`. Затем проведены запуски на вопросах досье.

## 2. Ошибка SSL при обращении к API

- **Задача / запрос к ИИ:** устранить ошибку проверки сертификата `SSLCertVerificationError` при подключении к GigaChat.
- **Предложение ИИ:** настроить доверенный CA bundle через переменную `GIGACHAT_CA_BUNDLE_FILE`, не отключая проверку сертификатов.
- **Решение команды:** использовать сертификат доверенного корня и локальные переменные среды.
- **Проверка:** после настройки тестовый запрос к API выполнился успешно.

## 3. Ошибка кодировки при запуске Python в Windows

- **Задача / запрос к ИИ:** разобраться с `UnicodeDecodeError`, возникавшей при чтении русскоязычных файлов проекта.
- **Предложение ИИ:** запускать скрипты с включённым UTF-8: `python -X utf8 ...`.
- **Решение команды:** использовать этот способ для запуска экспериментов, тестов и Streamlit в Windows.
- **Проверка:** последующие команды анализа и тестирования успешно выполнялись в PowerShell.

## 4. Невалидные ответы первой версии эксперимента

- **Задача / запрос к ИИ:** разобраться, почему часть ответов GigaChat не проходит Pydantic-валидацию.
- **Наблюдаемая ошибка:** в первом полном запуске `gigachat_baseline_v1` 14 из 36 ответов не соответствовали схеме; среди причин — логические значения `true`/`false` в поле `answer`, где требовалась строка или `null`.
- **Предложение ИИ:** явно указать в системном промпте допустимый тип поля `answer` и запретить булевы значения.
- **Решение команды:** исправить `prompts/system.txt` и повторить основной эксперимент, сохранив предыдущий запуск для диагностики.
- **Проверка:** в `gigachat_baseline_v2` все 36 ответов прошли проверку формата. 

## 5. Анализ основного сравнения A / B / C

- **Задача / запрос к ИИ:** объяснить метрики эксперимента и проверить, отличаются ли три способа подачи информации.
- **Предложение ИИ:** отдельно сравнивать точность статуса, качество ссылок на доказательства, валидность формата и время; не смешивать их в одну метрику.
- **Решение команды:** оставить режим A с полным досье, а для B и C использовать один и тот же набор из не более чем 15 утверждений; в C менять только их организацию по p-adic ветвям.
- **Проверка:** для `gigachat_baseline_v2` точность статуса равна 11/12 во всех трёх режимах. `evidence_f1`: A — 0,4056, B — 0,5694, C — 0,5056. Автоматические тесты проверяют совпадение выбранных ID и содержимого утверждений в B/C.

## 6. Логическая ошибка в первоначальном объяснении удаления посылки Q03

- **Задача / запрос к ИИ:** спроектировать стресс-тест, в котором после удаления необходимой посылки правильный статус меняется на `insufficient`.
- **Первоначальное предложение ИИ:** удалить утверждение C28 о том, что ресурс `arena_trial` отсутствовал на сервере.
- **Обнаруженная проблема:** в оставшемся журнале могло сохраниться сообщение `reason=resource_missing:arena_trial`, а в других документах — пересказы отсутствия ресурса. Простого удаления C28 недостаточно для гарантированного исчезновения соответствующего основания.
- **Решение команды:** не считать удаление одного ID достаточным; в подготовленном сценарии `remove_Q03` убрать также прямые указания на отсутствие ресурса из документов и журнала, сохраняя прочие события.
- **Проверка:** сопоставлены изменения D01, D02, D05, D08 в выводе `review_remaining_stress.py`. Проверены изменения D01, D02, D05 и D08.

## 9. Отклонение неподтверждённого объяснения результата перестановки

- **Задача / запрос к ИИ:** объяснить, что изменилось после перестановки десяти документов (`permutation_42`).
- **Первоначальное предложение ИИ:** связать ухудшение одного ответа в режиме B с новым порядком документов.
- **Проблема:** в режимах B/C передаются выбранные утверждения, а не полный упорядоченный список документов. Кроме того, повторные вызовы LLM способны давать разные ответы без изменения существенной информации.
- **Решение команды:** **отказаться** от причинного вывода «перестановка ухудшила BM25» как от недоказанного. Описывать только наблюдение: в B точность изменилась с 11/12 до 10/12; Q08 перешёл с `contradicted` на `insufficient`. Причина изменения не установлена.
- **Проверка:** сравнение сохранённых результатов «до / после» и логики формирования контекста B/C в коде.

- **Задача / запрос к ИИ:** проверить, заметит ли модель отсутствие необходимой посылки.
- **Предложение ИИ:** в сценарии `remove_Q04` удалить `actor=mira` из записи о входе в 18:10 и связанные с этим сведения, сохранив факт успешного входа.

## 12. Ошибка сортировки внутри p-adic ветви

- **Задача / запрос к ИИ:** проверить реализацию `src/padic.py`, включая порядок утверждений внутри ветвей.
- **Обнаруженная ошибка:** первоначальный ключ `occurred_at.isoformat()` сортировал строки времени лексикографически; при разных часовых поясах строковый порядок может не соответствовать хронологическому.
- **Предложение ИИ:** использовать `occurred_at.timestamp()` для сортировки абсолютных моментов времени, сохранив `None` в конце.
- **Решение команды:** заменить сортировку в `group_claims()`, не меняя трёхуровневое кодирование путей.
- **Проверка:** новая реализация присутствует в `src/padic.py`, после замены запуск обязательных тестов дал **20 passed**. Для исходного досье используется часовой пояс UTC+03:00.
